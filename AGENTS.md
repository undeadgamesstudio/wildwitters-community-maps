# AGENTS.md - wildwitters-community-maps

Guidance for coding agents (and people) working on the community maps repository.

## Credo (every Undead Games repository)

Code here is a template for what comes next (native iOS / Android apps, the next game), so it is written to be kept:

- **One responsibility per module.** A file that does several things is split by what it does, not by line count.
  An entry or controller wires the parts together and calls them; it does not contain them.
- **No oversized files or classes.** Around 400 lines is the point to look again; past that, split along the
  responsibilities that are already visible (sections, groups of functions sharing state). Shared state goes into one
  explicit object or context module, never into scattered module-level variables.
- **Reusable before copied.** Something a second place needs moves into a shared module (or a shared service, such as
  the mailer or the account service) instead of being duplicated.
- **Logic apart from the view.** Rules, data and flows are plain, testable code without DOM or framework; the view calls
  them. That keeps them usable from another front end.
- **Tests with the change.** New logic comes with tests; a refactor keeps every test green and is checked running.
- **Comments say why**, in the same plain style as the code around them; no file names of tools or chat history.
- Refactor only where it improves the architecture. A split that just moves lines around is not worth it.
